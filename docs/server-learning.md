# Central community learning — v6

Owner page: `/admin/community-learning.php`, linked from community-analysis settings. Community labels remain public and immediately contributed. Training is separate from draft-summary publication review.

- Event/match browsing is public. Helper v6 loads events after its setup check; sign-in is required to reserve work, not to load the dropdown. Reload events retries the chosen season.
- A training request creates a `community_learning_jobs` row. Duplicate clicks reuse the outstanding season job. A fixed, private PHP CLI worker is launched in the background; a MySQL named lock permits only one worker. The job continues after the browser closes. Hosts that disable background execution need that CLI worker scheduled separately.
- The worker snapshots current public labels directly from `community_video_labels`, with no user/browser/network identifiers. Snapshot, SHA, lifecycle state, reports, candidate JSON and benchmark JSON are stored in the database. Temporary video/crop files stay outside the web root. A server restart can discard that cache without erasing the source labels or saved reports.
- The initial classifier is the experimental robot-localized image/motion baseline, not a validated replacement for six scouts. It requires positive and explicit negative examples. No labels are inferred from missing tags. Current data readiness may skip video extraction entirely; that is not a failed training process.
- Each game has separate rules/fingerprint and model. 2025 rules are present, broadcast reader unverified; 2026 reader supported; 2027 not configured. Update canonical server packs through Maintenance Console. Helpers receive the appropriate pack from `/community/models.php?season=YYYY`.
- Resource limits: reduced process priority, BLAS/OMP single thread, CPU limit two hours, wall-time limit three hours. Long processing needs FFmpeg, yt-dlp, RapidOCR and ONNX Runtime on the server. Readiness reports require only Python 3. A custom Python environment can be installed at `/var/www/neptune/maintenance-uploads/community-learning-venv/bin/python3`; the worker otherwise uses `/usr/bin/python3`. The shipped `requirements-ocr.txt` specifies the existing OCR environment. Heavy OCR on a 2GB EC2 instance has not been load tested.
- Optional full six-robot reference set: `/var/www/neptune/maintenance-uploads/community-learning-benchmarks/YYYY/manifest.json`, using the existing benchmark format. The worker evaluates a trained candidate against it, retaining the results. An owner explicitly releases a passing model; candidate training never silently replaces the active model.
- Releases use `community_learning_releases`, separate from jobs. `/community/models.php` returns only a released, passing candidate. It checks that all used labels are still available and observed. A withdrawal disables the release on the next helper check. Helpers check before every match and do not use a stale local trained model when the server has no release or cannot be reached.
- Model distribution validates the game, feature version, contents hash and matching benchmark. Predictions remain uncertain observations. No points are attributed to robots from scoring-start labels.
